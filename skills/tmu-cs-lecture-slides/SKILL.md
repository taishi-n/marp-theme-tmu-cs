# TMU CS スライド

最初に対象の絶対パスと出力先を確認し，`AGENTS.md`，`PROJECT_POLICY.md`，既存の原稿，Makefileを読む．
研究固有の表記，掲載結果，比較条件，言語，章扉，引用数は，そのリポジトリの方針を優先する．
このスキルの例を理由に既存デッキの構成や言語を一律に変更しない．

本文や図を編集するときは[執筆規約](references/authoring.md)を読む．
新規デッキや構成変更では[用途別の設定](references/profiles.md)から講義，短い研究発表，実験報告の例を選ぶ．
音声を掲載するときは[音声比較](references/audio.md)を読む．
引用，CSS，索引，ビルドと検証は[公開機能の使い方](references/build.md)を参照する．

変更後は，利用者が不要と指定しない限り，対象デッキのHTMLをビルドして必要な静的検査を行う．
通常のビルドに毎回の許可確認を挟まない．
PDFは依頼された場合や配布物として必要な場合に，既存の生成コマンドで作る．
Chrome，Safari，headless browserを起動・操作して表示確認を行わない．
表示，文字の見切れ，音声の再生や体感速度は利用者が確認する．
完了報告では，生成物の絶対パス，実施したビルドと静的検査，表示確認が未実施であることを分けて示す．

文章や装飾の修正は，差分，ビルドと必要な静的確認で検証する．
旧表現の不在や特定ページの文言，CSSの値を固定するだけの恒久テストを増やさない．
新しい機能のテストは，継続する公開契約と具体的な故障を検出するために追加する．
