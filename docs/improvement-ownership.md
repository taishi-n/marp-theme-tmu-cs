# テーマ機能，作成スキル，個別リポジトリの責務分担

66項目の主な解決先を3つに再分類した．
番号は[元の項目一覧](improvement-items.md)を引き継ぎ，重複なくAに12項目，Bに43項目，Cに11項目を置く．
改善方法の提案P1〜P7も同じ3分類へ振り分けた．
2026-11-05に対応が承認された．実装状況は[実施状況](implementation-status.md)に記録する．

## 3分類の基準

| 分類 | 主な解決先 | 責務 |
| --- | --- | --- |
| A | このrepoの機能 | 正しい入力に対する表示，操作，生成結果の制御，再利用できるUIやCLI，依存パッケージとの統合 |
| B | `tmu-cs-lecture-slides`スキル | 複数のデッキで共通する執筆方針，既存機能の使い方，図の作成手順，ビルドと確認の進め方 |
| C | テーマを使う個別repo | 研究や発表に固有の内容，表記，データ，数値，採用結果，デッキ構成の具体的な決定 |

既存機能の指定で解決するものはBへ置き，新しい機能の実装を前提にしない．
スキルはCで定めた方針を読み，それに従って作成する．
機能側はCの研究内容やBの文章規約を自動判定して変換する処理を持たない．
wavegramに原因がある表示や操作の修正は，Aの依存先との統合として扱う．
必要な修正の実体をwavegram側に置く場合も，個別デッキの回避コードへ分散させない．

## B 作成スキルで扱う項目

| 番号 | スキルへ集約する内容 |
| --- | --- |
| 01〜07 | 1ページ1内容，短いタイトルと本文，ノートへの分離，細かい補足の抑制，実験条件と結果の説明順 |
| 09〜12，15，16 | 図の寸法と文字の統一，生成元での調整，図の表示面積，凡例の配置，SVGの利用 |
| 17，18 | 既存の列レイアウトやTeXの整列構文を使った比較と位置合わせ |
| 19，20，22〜26 | TeXでの記述，数式書体の一般的な既定，短い添字とアノテーション |
| 29，30 | 半角スラッシュと単位の括弧など，共通の表記方針 |
| 31，32 | 既存の引用パイプラインと任意CSL指定を使う手順，短い引用書式の例 |
| 38〜40 | 既存の補助ページ処理と`paginate: skip`を使う番号制御 |
| 42〜44 | 図表に根拠を持つ短い主張，下部メッセージを使うページ，タイトルとの役割分担 |
| 45〜48，50，51 | wavegramの利用，波形と操作部と時刻表示の設定，補助線の非表示，表示領域の調整 |
| 59〜63 | 編集後のHTMLビルド，必要時のPDFビルド，利用者による目視確認，通常ビルドの実行，検証範囲の選択 |

P1の共通執筆規約とP2の用途別作成例は，このrepoの一般文書へ蓄積する案から，スキルの参照資料へ集約する案に変更する．
P2では講義，短い発表，実験報告で設定の選び方を示し，内容や言語を一律に固定しない．
スキルの例はテーマの公開機能を使い，独自のHTML後処理やテーマの内部実装を複製しない．

調査時のスキルにはSafariでの確認手順，`sectionPages: true`を確認するチェック，古いwavegram属性を中心とした例が残っていた．
保守元を`skills/tmu-cs-lecture-slides/`へ置き，次の点を改善して個人スキルへ反映した．

- ブラウザの自動操作を標準手順から外し，ビルドと静的確認の結果だけを報告する．
- 章扉の有無はCのデッキ方針に従い，一律に有効化しない．
- wavegramの現在の`data-wavegram-*`を使い，生成後に設定を書き換えるJSを増やさない．
- 数式書体などの一般的な既定は，Cの原稿準拠の規約があればそちらを優先する．
- 文章や装飾の修正内容を固定する恒久テストを増やさない．

32は任意CSL指定で実現できるため，まずスキルの書式例として扱う．
脚注と文献一覧へ別々のCSLを指定する新機能が必要になった場合は，その部分を独立したAの追加要件として検討する．

40は初回計画で機能追加候補に含めていたが，既存機能で実現できると確認したためBへ移した．
付録の開始ページにグローバルな`<!-- paginate: skip -->`を置けば，後続の付録ページも番号が非表示となり，本編の合計から外れる．
本編2ページと付録2ページの一時的なレンダリングで，本編の合計が2となることを確認した．
付録の内容を索引として構造化するかどうかは，番号制御とは別のP3で扱う．

50は現在のwavegramのCSS変数`--ap-spectrogram-tick`を使った設定で対応できる．
利用側で使われている`transparent`指定をスキルの例に取り込み，新しい描画APIの追加を前提にしない．

| 53，54 | 1手法を1ページにするか，どの試聴例を載せ，どの対応や性能を説明するか |

P7のFFT，hop，dB範囲などの具体的な比較条件もCへ置く．
スキルは比較条件を揃える手順を共通化し，実際の値は個別repoの設定から読む．
用語集や数式表記は個別repoの`AGENTS.md`，仕様書，図や音声の設定ファイルなどへまとめる．
同じ研究のレポートと複数デッキでは，そのrepo内の共通定義を参照する．
